## What exists

A dark, space-themed learning-path page, behind a login gate, with an insights/account UI in the nav:
- Hero animation (kept unchanged; a small "SSIS to Fabric in 11 weeks" eyebrow line sits above it), 11-week route chart, "where you start" (translation table), freshness check table, 6 phases, stretch missions, guardrails.
- 50 tasks in 6 phases. **Phase 2 is a pilot with 24 lessons** (Learn, Try it, Break it, Prove it, self-test questions, copyable code). Other phases are task lists only.
- **Login gate** (`js/auth.js`): a full-page splash checks the Supabase session, then shows either a login card (email/password) or the app — the app's markup (`header.nav`, `main`, `footer`) is `display:none` by default in CSS and only revealed once JS confirms a session or local-only mode, so there's no flash of content before login. A cosmetic 60-second lockout follows 5 failed sign-in attempts (client-side counter, not enforced server-side). If `config.js` has no URL/key, the gate is skipped entirely and a "local-only mode" banner shows instead — this is a lock screen only: lesson text is still in the page source regardless of login state; the real protection is Row Level Security on the Supabase tables. See README "Login and privacy".
- **Insights pill and account circle** (top-right of the nav, both built in `js/app.js`'s `bindInsights()`): the pill shows the progress ring, percentage, a status dot and "Saved on this device · <IST time>" (collapses to ring+dot only at 900px and narrower); clicking it opens a panel (popover ≥900px, bottom sheet below) with completion/lesson/estimated-hours counts, a thin bar per phase, current phase and next task (`nextItem()` reused, "Open it" reuses `openNext()`), saving status, and an optional start-date control showing "Week N of 11" and a planned-vs-done hours estimate. The account circle (first letter of the signed-in email) is hidden entirely in local-only mode or when signed out; its menu has the email, Export/Import progress (same feature as the footer buttons, triggered via `.click()` on the existing `#exportProgress`/`#importProgress`/`#signOut` buttons rather than duplicating the logic), Sign out, and Sign out and clear this device (wipes `ssis-to-fabric-path-v2` and `ssis-to-fabric-path-meta` from `localStorage`, then signs out). Both the pill's panel and the account menu are real dialogs: `Escape` and outside-click close them, focus is trapped while open (Tab-wrap in the panel, arrow keys in the menu) and returns to the opening button on close.
- Times are always shown in IST regardless of the visitor's device time zone (`fmtIST()` in `js/app.js`, built on `Intl.DateTimeFormat` with an explicit `timeZone:"Asia/Kolkata"`; verified against device time zones UTC, America/New_York and Asia/Kolkata all producing the same displayed time). No polling: the pill/panel only update on events (tick/untick/reset/import via `noteChange()`, sign-in via `onAuthStateChange`).
- Progress is stored in `localStorage` under key `ssis-to-fabric-path-v3`: `{ v:1, items: { "<id>": [1|0, timestampMs] } }`, one entry per task or lesson id with a per-item last-change timestamp. The legacy flat `ssis-to-fabric-path-v2` (`{ "<id>": 1 }`) is migrated into v3 once, on first load after this update, if v3 doesn't exist yet and v2 does — migrated items all get the same "now" timestamp, and v3 is only written if there was actually something to migrate (an eagerly-written empty v3 would wrongly look "already migrated" and block a v2 write arriving later, e.g. from an older cached tab — this was a real bug, caught by testing, fixed before it shipped). Neither `v2` nor `v3` has been renamed and neither should be. A task with lessons is done when all its lessons are done (derived, never stored). A second key, `ssis-to-fabric-path-meta`, holds `{ lastSavedAt, lastChangeAt, startDate }`. Progress now syncs to `public.progress` — see "Sync" below; notes still don't (that's phase 4).
- **Sync** (`js/app.js`, top-level functions, not nested in `bindInsights`): local-first. Every tick/untick/reset/import writes `localStorage` immediately (`persistItems()`), then `scheduleSync()` debounces (~800ms) an upsert of `{v:1, items, meta:{startDate}}` to `public.progress` (`runSync()`), with exponential backoff retry on failure (2s, doubling, capped at 60s, reset to 2s on success). A `localGen`/`savedGen` pair of counters stops a save that was in flight when a newer local edit landed from wrongly marking things "saved" — if generations don't match when a save completes, it immediately reschedules another. `pullAndMerge()` fetches the remote row and merges it into local `items` per-item, latest timestamp wins (`mergeItems()`), then always pushes the (possibly just-merged) result back — this single function handles "first login on a device: upload local progress if remote is empty, otherwise merge" simply by doing nothing in the merge step when there's nothing remote to merge. It runs on sign-in (once per session, guarded by `hasPulledThisSession`), on `visibilitychange` (tab regains focus) and on the `online` event; the `offline` event just sets the "offline" sync state (no timer — it waits for the `online` event to resume). `meta.lastSavedAt` updates on every successful cloud save. The insights pill/panel's `syncStatus()` now reflects four real states (saved/saving/offline/error) instead of always "local only", falling back to the pre-sync "Saved on this device" wording only when there's no `window.APP_AUTH_CLIENT` (local-only mode) at all.
- **Sign-out is gated by sync state** (`guardSignOut()` in `js/app.js`, exposed as `window.APP_SYNC.guardSignOut`, called from both the footer's Sign out button in `js/auth.js` — via `window.APP_AUTH_SIGNOUT`, the raw ungated sign-out, to avoid double-guarding when the account menu triggers the same button — and the account menu's Sign out / Sign out and clear this device): if a save is in flight, it waits for it (up to 8s) before deciding anything. If the current state is clean (not dirty, not error, not offline), it proceeds immediately. Otherwise it opens `#syncWarn`, a small dialog (`role="alertdialog"`, focus-trapped, `Escape` closes) offering Export progress (opens the existing export dialog, doesn't sign out), Sign out anyway (proceeds despite the risk) or Cancel (does nothing). Clear-device additionally only wipes `localStorage` (`ssis-to-fabric-path-v2`, `-v3`, `-meta`) *after* the guard's proceed decision, never before — confirmed by test that ticking a task, forcing a cloud failure, then choosing Clear-device shows the warning and leaves the ticked task in place until "Sign out anyway" is chosen.
- Export/import progress as JSON from the footer (clipboard, with a select-and-copy fallback; import is validated against known task/lesson ids, unrecognised ids are skipped, valid ones are merged into existing progress rather than replacing it). Also reachable from the account menu.
- No job-search content: it was deliberately removed (see "Pending work" below for what changed).
- It was also published as a claude.ai artifact. The page has no `window.claude` calls, so it runs anywhere (though the login gate now needs a reachable Supabase project, or `config.js` left empty, to behave sensibly).

## How the file is organised (search for these markers)

- `index.html` `<head>`: loads `js/early.js` synchronously (defines `window.BRAND`, sets `document.title`/meta description from it, then adds the `.js` class before first paint so `.rv` reveal animations start hidden) then the page's own `<style>` block (dark-only tokens in `:root`; sections: deep space layers, slow arrivals (`.rv`), nav, insights pill/account circle, insights panel, hero, route, phases + trajectory, tasks with lessons, import/export panel, login gate, gutters (wide screens), reduced-motion block at the end).
- `<body>`: `#gate` (splash + login card, `position:fixed`, highest z-index) right at the top so it overlays everything immediately, then `#cosmos` (star layers, nebulae, planets, aura), `#rail` and `#orbit` (wide-screen gutters), `#fx` (burst canvas), `#localBanner` (local-only mode notice, normal flow, sits above the nav when shown), then `header.nav` (brand, nav-links, `.nav-right` holding `#insightsPill` and `#accountWrap`/`#accountMenu`), `#insightsPanel` (sits right after `</header>`, not nested inside the nav, since it's `position:fixed`), `main` with sections `#route #start #fresh #path #stretch #guardrails`, footer (reset/export/import/sign out), the `#ioPanel` export/import dialog, and `#syncWarn` (the "not saved to the cloud yet" dialog before a sign-out or clear-device that would risk losing something). `header.nav`, `main` and `footer` are hidden by CSS (`html:not(.gate-open) ...{display:none}`) until `js/auth.js` adds the `gate-open` class to `<html>`.
- End of body, in dependency order: `config.js` (blocking, sets `window.APP_CONFIG`), then three **deferred** scripts in this order — the pinned `@supabase/supabase-js` UMD build from jsDelivr, `js/auth.js`, `js/app.js`. All deferred scripts run after parsing completes, in source order, so each one can rely on the previous having already run.
- `js/auth.js`: reads `window.APP_CONFIG`; if missing/empty or if `window.supabase` failed to load, falls open to local-only mode (banner shown, gate skipped, no login). Otherwise creates the Supabase client (exposed as `window.APP_AUTH_CLIENT` for `js/app.js` and the future sync layer to use), checks `getSession()`, shows the login card if there's no session, handles `signInWithPassword`, the lockout counter, `signOut`, and `onAuthStateChange`. Also sets the login `<h2>` from `window.BRAND`.
- `js/app.js` (one IIFE), in this order: helpers, **content data** (`P0 P1 P2 P3 P4 P5`, `STRETCH`, `ROSETTA`, `FRESH`, `COSTS`), state (`items`/`done`/`setItem`/`rebuildDone`/`persistItems`/`persist`/`taskDone`/`KNOWN_IDS`/`TOTAL_HOURS`, `meta`/`persistMeta`/`noteChange`), renderers (`renderRoute`, `renderStatic`, `renderPhases`, `lessonHTML`), refresh + interactions (`bindIO` for export/import, then time/stats helpers `fmtIST`/`istParts`/`istDateKey`/`computeStats`/`weekInfo`/`renderInsightsPanel`, the **sync engine** — `runSync`/`scheduleSync`/`scheduleRetry`/`mergeItems`/`pullAndMerge`/`guardSignOut`/`openSyncWarn`/`syncStatus`/`updateSyncUI`, exposing `window.APP_SYNC.guardSignOut` — a small `focusables`/`trapTab` pair reused by all three dialogs, and `bindInsights` for the pill/panel/account menu, which also wires the sync triggers: sign-in, `visibilitychange`, `online`/`offline`), `cosmos()`, `hero()`, boot (which also sets `#brandText`/`#brandLink`'s aria-label from `BRAND` and calls `updateSyncUI()` once). It knows nothing about auth beyond reading `window.APP_AUTH_CLIENT` for the account circle's own `getSession()`/`onAuthStateChange` calls (a second, independent subscription from auth.js's — Supabase supports multiple listeners) and for the sync engine's own calls; `js/auth.js` and the CSS decide whether the rest of the DOM is visible. `js/auth.js` exposes `window.APP_AUTH_SIGNOUT` (the raw, ungated sign-out) for `js/app.js` to call after its own guard passes.
- Lessons render lazily on first open (`ensureLesson`). Code is stored with `String.raw` (`R` tag); never put a backtick or `${` inside lesson code.
- Phase object shape: `{id,n,short,name,layer,layerName,weeks,hours,cost,tone,needs,goal,tasks[],ship,note,bridge[],links[]}`. Task: `{id,t,d,subs?}`. Lesson: `{id,t,mins,learn[],try[],expect,brk,prove[],quiz[],watch,links}`.
- The `js/early.js` / `js/app.js` split (and `js/auth.js`) exists only to satisfy the Content-Security-Policy in `netlify.toml` (`script-src 'self' https://cdn.jsdelivr.net`, no `'unsafe-inline'`). If the CSP ever needs to change, keep in mind `early.js` must stay a blocking, non-deferred `<head>` script or the `.js`-class-before-paint (and title/meta) behaviour breaks; `config.js` must run before the deferred scripts, which it does by being a blocking script placed just before them.

## Design decisions worth keeping

- Layer colours mean something: bronze = foundations, silver = core engineering, gold = production and proof. Phase markers are planets; the glowing probe follows scroll.
- Performance work is done: stars are pre-rendered tiles animated by CSS, scroll work is event-driven, no `backdrop-filter`, `content-visibility:auto` on lower sections, lessons lazy-rendered. Measured (headless Chromium, 1890px): idle JS about 6 ms/s, scroll JS about 9 ms/s, about 1,550 DOM nodes. Do not reintroduce per-frame full-canvas redraws or a root CSS variable updated on scroll.
- `body{isolation:isolate}` is required. Without it the `#cosmos` layer paints under the body background and the sides look plain black (this was a real bug).
- Respects `prefers-reduced-motion` (CSS kills animations, JS avoids loops).
- Copy style: plain sentences, no em dashes, UK spelling in prose, no filler.

## How to test locally
- Syntax: extract the `<script>` body and run `node --check`.
- Behaviour: Playwright (Python or Node) against `file:///.../index.html`. Useful checks: no console errors (ignore the blocked Google Fonts request in sandboxes), `document.documentElement.scrollWidth === viewport width` on a 390px viewport, open a lesson, tick it, confirm the task becomes done and the progress survives a reload.
- Measure JS cost by wrapping `requestAnimationFrame` and summing callback time while idling and scrolling.
